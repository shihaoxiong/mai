# Java DeerFlow Backend 需求文档

## 1. 文档目标

本文定义基于 Spring AI Alibaba 实现的 Java 版 DeerFlow backend 的业务目标、范围边界、功能需求与非功能需求，作为后续架构设计和研发排期的输入。

## 2. 项目目标

构建一套面向长期工作任务的 Agent Backend，满足以下目标：

- 支持长会话、长任务、多步骤推理和恢复执行。
- 提供线程隔离的工作区、上传区、输出区，支持 Agent 长时间操作文件。
- 支持工具、MCP、Skills、Memory、Subagent 等扩展机制。
- 提供完整平台 API，便于前端、运维与二次开发接入。
- 基于 Spring AI Alibaba，形成可维护的 Java 技术栈方案。

## 3. 范围说明

### 3.1 本期范围

- Backend runtime 与 platform API。
- 面向 DeerFlow 风格前端的接口设计。
- Spring AI Alibaba 运行时适配与二次封装。
- 本地开发环境与生产部署架构设计。

### 3.2 非目标

- 本期不追求 DeerFlow Python 内部结构 1:1 对齐。
- 本期不实现完整 IM 通道接入（Feishu/Slack/Telegram）。
- 本期不实现完整多租户计费系统。
- 本期不要求一次性覆盖所有第三方 community tool。

## 4. 目标用户

### 4.1 终端用户

- 通过 Web UI 发起长期任务、上传资料、查看产物、处理审批。

### 4.2 Agent 应用开发者

- 配置模型、工具、MCP、技能。
- 编写或安装 Skills。
- 观测线程状态、排查任务故障。

### 4.3 平台运维/管理员

- 管理模型配置、MCP 服务、Sandbox、存储与日志。

## 5. 产品能力范围

### 5.1 MVP

- 线程管理与恢复执行。
- 流式 Agent 执行。
- 线程工作区、上传区、输出区。
- Built-in 工具与 MCP 工具。
- 文件上传和文档转 Markdown。
- 基础 Skills 注入与开关。
- 短期记忆、上下文压缩、规划模式。
- 子任务编排的第一版。
- 产物访问与线程清理。

### 5.2 V1.1

- 长期记忆抽取与用户画像沉淀。
- 技能安装、版本与依赖校验。
- 审批/澄清工作台。
- 标题生成、建议问题生成。
- Docker sandbox、审计日志、细粒度权限。

## 6. 功能需求

### FR-01 线程生命周期管理

系统必须：

- 以 `threadId` 作为长期任务会话主键。
- 支持线程创建、查询、删除、恢复。
- 删除线程时，同时删除 checkpoint 关联资源和线程目录资源。
- 支持通过 `threadId` 恢复历史执行状态并继续运行。

验收标准：

- 同一 `threadId` 下多次调用可延续上下文。
- 删除线程后，线程目录不可继续访问。

### FR-02 Agent 运行与流式输出

系统必须：

- 提供运行接口，支持用户消息驱动 Lead Agent 执行。
- 提供实时流式输出能力，向前端持续推送 token、工具调用、状态变化、审批中断、子任务进度等事件。
- 支持运行结束、失败、中断、待审批、待澄清等状态。

验收标准：

- 长任务执行时前端可看到中间状态。
- 网络抖动后能够基于 thread/checkpoint 恢复。

### FR-03 工作流与规划能力

系统必须：

- 支持多步骤任务的计划生成与待办列表维护。
- 支持在关键步骤暂停，等待人工审批或澄清。
- 支持审批后恢复执行，而不是从头重跑整个任务。

验收标准：

- 复杂任务可输出结构化待办列表。
- 审批通过/拒绝可改变后续执行路径。

### FR-04 线程隔离工作区与 Sandbox

系统必须：

- 为每个线程创建独立 `workspace`、`uploads`、`outputs` 目录。
- Agent 只能通过虚拟路径访问其线程范围内的文件。
- 提供本地开发 Sandbox 与生产级隔离 Sandbox 两种实现。
- 支持命令执行、目录列举、文件读写、文件替换等基础工具。

验收标准：

- 不同线程之间不能互相访问对方文件。
- 非法路径访问会被拒绝并记录审计日志。

### FR-05 文件上传与文档预处理

系统必须：

- 支持多文件上传。
- 对 PDF、PPT、Excel、Word 自动转换为 Markdown。
- 在后续 Agent 运行中自动注入可访问文件列表。
- 支持文件列表、删除和下载/预览。

验收标准：

- 上传成功后，Agent 下一轮能直接看到文件及虚拟路径。
- 文档转换失败时保留原文件并返回可诊断信息。

### FR-06 技能系统

系统必须：

- 支持技能发现、启用、禁用、详情查看。
- 支持将启用技能注入 Agent 上下文。
- 支持技能安装的扩展点，便于后续接入压缩包/仓库安装。

验收标准：

- 启用技能后，下一轮运行可生效。
- 禁用技能后，不再进入上下文。

### FR-07 MCP 工具接入

系统必须：

- 支持配置多个 MCP Server。
- 支持启用/禁用、基础参数修改与热加载。
- 将 MCP 能力统一暴露给 Agent Tool Registry。

验收标准：

- 配置更新后无需重启应用即可生效。
- 不可用的 MCP Server 不影响其他工具运行。

### FR-08 模型管理

系统必须：

- 支持多模型注册与查询。
- 支持标记模型能力，如 vision、thinking、structured output。
- 支持为不同 Agent / Hook / Summarizer 选择不同模型。

验收标准：

- 前端可查询模型列表和能力标签。
- 标题生成、总结、主 Agent 可使用不同模型配置。

### FR-09 记忆系统

系统必须：

- 具备 thread 级短期记忆。
- 提供跨线程的长期记忆存储抽象。
- 支持在运行前注入记忆，在运行后异步抽取记忆。
- 支持配置记忆条数、置信度和注入策略。

验收标准：

- 同一用户跨线程可复用长期记忆。
- 记忆提取任务失败不影响主任务成功返回。

### FR-10 子任务与多 Agent 编排

系统必须：

- 支持主 Agent 将子任务委派给子 Agent。
- 支持串行、并行、监督者路由等编排模式。
- 支持子任务超时、取消、状态跟踪与结果汇总。

验收标准：

- 子任务状态可查询。
- 子任务失败可返回给主 Agent 作为观察结果继续决策。

### FR-11 产物管理

系统必须：

- 支持 Agent 在 `outputs` 目录生成产物。
- 提供 HTTP 访问、下载与预览接口。
- 记录产物元数据，便于前端展示。

验收标准：

- 线程内生成的文件能通过产物接口访问。
- 越权访问其他线程产物会被拒绝。

### FR-12 配置与运维 API

系统必须：

- 提供模型、技能、MCP、线程、运行状态等管理接口。
- 支持配置热加载。
- 暴露健康检查、指标、审计日志和错误诊断信息。

验收标准：

- 关键配置变更不需要重启应用。
- 运维能快速定位线程执行失败原因。

## 7. 非功能需求

### NFR-01 可恢复性

- 长任务中断后应能基于 checkpoint 恢复。
- 审批中断、模型调用失败、节点重试等不应导致线程状态丢失。

### NFR-02 性能

- 普通对话首包时间目标小于 3 秒。
- 流式事件应稳定输出，不因单个耗时工具完全阻塞 UI 感知。
- 10 分钟以上长任务需要保证状态持久化与心跳可见性。

### NFR-03 扩展性

- 模型、MCP、Skills、Sandbox、Memory Store 必须可插拔。
- 运行时与平台 API 需支持后续拆分部署。

### NFR-04 安全性

- 文件访问需防止目录遍历。
- 高风险工具需支持审批与审计。
- 密钥不得明文保存在业务配置中，应支持环境变量或密钥服务解析。

### NFR-05 可观测性

- 需要具备运行日志、工具调用日志、线程状态日志、性能指标。
- 后续应能接入链路追踪与调用成本分析。

### NFR-06 兼容性

- 尽量复用 DeerFlow 前端交互模型与 API 习惯。
- 兼容本地部署与容器化部署。

## 8. 核心实体

- `Thread`：长期任务会话。
- `Run`：一次具体执行。
- `ThreadWorkspace`：线程目录上下文。
- `UploadFile`：上传文件及其 Markdown 派生文件。
- `Artifact`：Agent 生成的输出文件。
- `Skill`：可开关的技能包。
- `McpServerConfig`：MCP 服务配置。
- `MemoryFact`：抽取出的长期记忆事实。
- `SubTask`：子任务执行实例。
- `ApprovalTask`：待审批/待澄清任务。

## 9. 优先级建议

### P0

- Thread + checkpoint
- 流式执行
- workspace/uploads/outputs
- 基础工具与 sandbox
- MCP
- 文件上传与 Markdown 转换
- 产物访问

### P1

- Skills 开关
- 规划模式
- 审批恢复
- 子任务编排
- 长期记忆抽取

### P2

- 技能安装
- 标题/建议生成
- 审计与权限细化
- 多租户与配额

## 10. 发布边界建议

### MVP 发布条件

- 核心运行链路稳定。
- 至少支持一个生产模型提供方。
- 支持一个生产可用的 MCP 场景。
- 支持文件上传、产物访问、线程恢复。
- 有基础日志、健康检查和错误处理。

### V1 发布条件

- 子任务编排可用。
- 记忆系统可用。
- 审批恢复可用。
- 技能与 MCP 配置可热更新。
